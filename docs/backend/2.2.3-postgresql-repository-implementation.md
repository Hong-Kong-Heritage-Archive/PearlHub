# Chat 2.2.3 — PostgreSQL Repository Implementation & Query Hardening

## Objective

Complete and harden the PostgreSQL repository adapter against the schema frozen in Chat 2.2.2.

```text
Domain / Application
        ↓
Repository Ports
        ↓
PostgreSQL Adapter
        ↓
Frozen PostgreSQL Schema
```

## Frozen inputs

Do not modify `migrations/001_initial.sql` or `migrations/002_persistence_hardening.sql`. Preserve repository ports and frozen domain invariants.

## Repository scope

### ArtifactRepository
`findById`, `findByOwnerAndSlug`, `create`, `save`.

Verify row mapping, null behaviour, complete create, mutable-only save, immutable identity, and stable constraint errors.

### ArtifactVersionRepository
`findById`, `findByArtifactAndVersion`, `findForArtifact`, `findLatest`, `create`.

Verify identity, immutability, duplicates, empty collections, deterministic ordering, and SemVer-aware latest selection.

`findLatest()` must not use lexical `ORDER BY version DESC`. If SQL SemVer ordering would duplicate/approximate domain semantics, retain `semver.rcompare()` in application code and document the decision.

### LineageRepository
`createFork`, `getParents`, `getChildren`.

Verify fork-only semantics, no self-lineage, duplicate rejection, FK integrity, deterministic ordering.

### ProvenanceRepository
`create`, `findForVersion`.

Verify version ownership, empty results, deterministic ordering, and GitHub provenance semantics.

### DependencyRepository
`findForVersion`, `create`, `createResolution`, `findResolutions`.

Verify source version, target Artifact, exact declared range, concrete resolution, target-version integrity, deterministic ordering. Repository does not reinterpret SemVer ranges.

### CompatibilityReportRepository
`create`, `findForArtifactVersion`.

Verify source version, nullable target, JSONB round-trip, status, deterministic ordering, empty results.

## Error mapping

Harden `translateConstraints()` with priority:

```text
SQLSTATE → constraint name → other metadata
```

Verify UNIQUE, FK, CHECK, immutable trigger, duplicate lineage, duplicate slug, duplicate version. Unexpected DB failures remain diagnosable.

## Transaction manager

Verify BEGIN/COMMIT, BEGIN/ROLLBACK, shared client across repositories, release, rollback on failure, no client leakage, and documented nested transaction behaviour if unsupported.

## Integration tests

Real PostgreSQL only. Cover reads/writes, empty/not-found cases, mapping, constraints, immutable fields, lineage, provenance, dependency cross-target rejection, compatibility JSONB, rollback, and concurrent duplicate owner/slug.

## Query hardening

Review parameterisation, deterministic ordering, FK filtering, cross-artifact safety, nullable handling, explicit columns where useful, and existing indexes. Do not add indexes or change schema.

## Out of scope

HTTP framework, API endpoints, auth, Playground, search, metrics, durable content storage, object storage, background jobs, deployment, microservices, ORM/query builder.

## Acceptance criteria

- Every PostgreSQL repository audited.
- Domain ↔ DB mapping correct.
- SQL parameterised.
- Observable collection ordering deterministic.
- `findLatest()` respects SemVer.
- DB errors map to stable application/domain codes.
- Transactions verified.
- Real PostgreSQL integration tests pass.
- Concurrency remains correct.
- Migrations unchanged.
- No ORM/query builder/framework introduced.
- `npm run build` passes.
- `npm run test:unit` passes.
- `npm run test:integration` passes.
- Final report documents changes and unresolved questions.

Then stop.
