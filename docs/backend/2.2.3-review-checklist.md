## Verification Notes
- Repository reads use explicit columns where relevant, parameterized values, and deterministic ordering with stable ID tie-breakers.
- `findLatest()` loads the artifact's versions and applies `semver.rcompare()` in application code; SQL lexical ordering is not SemVer ordering. SemVer 2 build metadata is accepted and tested.
- Persistence errors are classified by SQLSTATE first, then refined by constraint name; message metadata is only a fallback for the immutable-version trigger. Unknown database errors are rethrown unchanged.
- No indexes were added. Version selection uses the existing artifact-version index and in-memory SemVer sorting; collections remain unpaginated per the frozen ports.
- Changed implementation and tests: `src/adapters/postgres.ts`, `src/domain/semver.ts`, `tests/integration/postgres.test.ts`, and `tests/unit/domain.test.ts`.
- Frozen migrations and `src/ports/repositories.ts` are unchanged. No framework, ORM, query builder, or schema change was introduced.
- No outstanding questions; nested transactions are explicitly unsupported as documented above.
