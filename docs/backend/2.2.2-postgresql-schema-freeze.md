# Chat 2.2.2 — PostgreSQL Schema Freeze

## Objective

Freeze the PostgreSQL persistence contract after:

- Chat 2.1 — Backend Domain / Schema / Repository / API Contract
- Chat 2.2.1 — PostgreSQL Persistence Hardening

This is schema-contract work, not HTTP/API/framework work.

## Core tables

Freeze exactly these core tables:

1. `users`
2. `artifacts`
3. `artifact_versions`
4. `artifact_lineage`
5. `provenances`
6. `dependencies`
7. `dependency_resolutions`
8. `compatibility_reports`

Do not add metrics, stars, Playground, search, auth-provider, content-provider, job, or audit tables.

## `users`

Conceptual contract:

```text
id UUID PRIMARY KEY
external_subject TEXT UNIQUE NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
```

Do not introduce provider-specific authentication columns.

## `artifacts`

Conceptual contract:

```text
id UUID PRIMARY KEY
owner_id UUID NOT NULL REFERENCES users(id)
name TEXT NOT NULL
slug TEXT NOT NULL
visibility TEXT NOT NULL
status TEXT NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
```

Required:

```text
UNIQUE(owner_id, slug)
visibility ∈ {private, unlisted, public}
status ∈ {active, tombstone}
status=tombstone => visibility=unlisted
owner_id immutable
name immutable
slug immutable
physical DELETE rejected
```

Slug is owner-scoped, not globally unique.

Normal lifecycle updates must still allow appropriate `visibility`, `status`, and `updated_at` changes.

Deletion is a tombstone; preserve existing versions, provenance, dependencies, and lineage according to the existing FK model.

## `artifact_versions`

Conceptual contract:

```text
id UUID PRIMARY KEY
artifact_id UUID NOT NULL REFERENCES artifacts(id)
version TEXT NOT NULL
content_hash TEXT NOT NULL
content_location TEXT NOT NULL
created_at TIMESTAMPTZ NOT NULL
published_at TIMESTAMPTZ NOT NULL
```

Required:

```text
UNIQUE(artifact_id, version)
UNIQUE(artifact_id, content_hash)
published version immutable
```

Immutability covers:

```text
artifact_id
version
content_hash
content_location
created_at
published_at
```

SemVer parsing remains domain/application responsibility. Do not implement full SemVer validation in PostgreSQL.

## `artifact_lineage`

Conceptual contract:

```text
id UUID PRIMARY KEY
parent_artifact_id UUID NOT NULL REFERENCES artifacts(id)
child_artifact_id UUID NOT NULL REFERENCES artifacts(id)
relationship_type TEXT NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Required:

```text
relationship_type = fork
parent_artifact_id <> child_artifact_id
UNIQUE(parent_artifact_id, child_artifact_id, relationship_type)
```

Fork creates permanent lineage. Clone creates no lineage. No Merge or Branch.

## `provenances`

Conceptual contract:

```text
id UUID PRIMARY KEY
artifact_version_id UUID NOT NULL REFERENCES artifact_versions(id)
source_type TEXT NOT NULL
source_url TEXT NOT NULL
source_ref TEXT NOT NULL
imported_at TIMESTAMPTZ NOT NULL
```

GitHub import is provenance/source metadata, not Fork lineage.

## `dependencies`

Conceptual contract:

```text
id UUID PRIMARY KEY
artifact_version_id UUID NOT NULL REFERENCES artifact_versions(id)
target_artifact_id UUID NOT NULL REFERENCES artifacts(id)
declared_range TEXT NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

`declared_range` is a SemVer range stored as text. PostgreSQL does not parse it.

## `dependency_resolutions`

Conceptual contract:

```text
id UUID PRIMARY KEY
dependency_id UUID NOT NULL REFERENCES dependencies(id)
resolved_artifact_version_id UUID NOT NULL REFERENCES artifact_versions(id)
resolved_at TIMESTAMPTZ NOT NULL
```

Mandatory DB integrity:

```text
resolved_artifact_version.artifact_id
=
dependency.target_artifact_id
```

Chat 2.2.1 introduced DB-level protection for this. Preserve it.

If an internal helper column such as `target_artifact_id` is used, keep it as a PostgreSQL persistence implementation detail unless the public domain/repository contract actually requires it.

## `compatibility_reports`

Conceptual contract:

```text
id UUID PRIMARY KEY
artifact_version_id UUID NOT NULL REFERENCES artifact_versions(id)
target_artifact_version_id UUID NULL REFERENCES artifact_versions(id)
status TEXT NOT NULL
report JSONB NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Keep compatibility as a separate record.

## Constraint inventory

Verify all:

### Primary keys
Every table has its UUID primary key.

### Foreign keys

```text
artifacts.owner_id -> users.id
artifact_versions.artifact_id -> artifacts.id
artifact_lineage.parent_artifact_id -> artifacts.id
artifact_lineage.child_artifact_id -> artifacts.id
provenances.artifact_version_id -> artifact_versions.id
dependencies.artifact_version_id -> artifact_versions.id
dependencies.target_artifact_id -> artifacts.id
dependency_resolutions.dependency_id -> dependencies.id
dependency_resolutions.resolved_artifact_version_id -> artifact_versions.id
compatibility_reports.artifact_version_id -> artifact_versions.id
compatibility_reports.target_artifact_version_id -> artifact_versions.id
```

Do not replace FK enforcement with application existence checks.

### Unique constraints

At minimum:

```text
users.external_subject
artifacts(owner_id, slug)
artifact_versions(artifact_id, version)
artifact_versions(artifact_id, content_hash)
artifact_lineage(parent_artifact_id, child_artifact_id, relationship_type)
```

Plus composite keys needed by dependency-resolution target integrity.

### Check constraints

Verify:

```text
Artifact visibility
Artifact status
tombstone => unlisted
lineage relationship_type = fork
lineage parent != child
```

Do not use PostgreSQL checks for full SemVer parsing.

### Triggers

Verify the existing triggers for:

```text
Artifact identity immutability
Artifact physical-delete rejection
Artifact Version immutability
Dependency resolution target integrity
```

Prefer CHECK/FK/UNIQUE over triggers where sufficient, but do not remove an existing required immutability trigger.

## Index review

Review actual repository queries before adding indexes.

At minimum inspect:

```text
artifacts(owner_id)
artifacts(visibility, status)
artifact_versions(artifact_id)
artifact_lineage(parent_artifact_id)
artifact_lineage(child_artifact_id)
provenances(artifact_version_id)
dependencies(artifact_version_id)
dependencies(target_artifact_id)
dependency_resolutions(dependency_id)
compatibility_reports(artifact_version_id)
compatibility_reports(target_artifact_version_id)
```

Do not blindly add every index. Existing PK/UNIQUE indexes may already cover access patterns. Document any new index and its query/use case.

## Migration freeze

```text

```

1. Do not modify `001_initial.sql`.

4. Never rewrite migration history.
5. Do not add a migration solely for documentation.
6. Do not introduce destructive changes.
7. Do not introduce an ORM migration system.

Prefer verification/documentation over schema modification in this task.
